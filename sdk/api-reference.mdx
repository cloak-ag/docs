This page tracks the current public exports of `@cloak.dev/sdk`.

## UTXO API

The UTXO free functions are the primary entrypoint. There is no client class to construct.

```typescript
transact(params, options)
transfer(inputUtxos, recipientPubkey, amount, options)
partialWithdraw(inputUtxos, recipient, withdrawAmount, options)
fullWithdraw(inputUtxos, recipient, options)
swapUtxo(params, options)
swapWithChange(inputUtxos, swapAmount, outputMint, recipientAta, minOutputAmount, options, recipientWallet?)
```

`transact` is the single engine entrypoint and the sign of `externalAmount` classifies the
flow: positive shields (deposit), negative withdraws, zero is a shielded transfer.
`transfer`, `partialWithdraw` and `fullWithdraw` are shaped wrappers over it.

Every one of these takes a `TransactOptions` object. `connection`, `programId` and `relayUrl`
are required on all flows; supply either `depositorKeypair` (programmatic) or the wallet
callbacks `signTransaction` / `signMessage` plus `walletPublicKey` (browser). `relayUrl` has
no default and is not read from the environment, so pass it explicitly on every call. Every flow
except a deposit needs an authenticated sender and throws before proof generation without one:
see [Request authentication](/sdk/request-authentication).

UTXO primitives:

```typescript

```

## Result types

Every UTXO flow resolves to a `TransactResult`:

```typescript
interface TransactResult {
  signature: string;
  inputNullifiers: bigint[];
  outputCommitments: bigint[];
  newRoot: string;
  commitmentIndices: [number, number];
  siblingCommitments: [bigint, bigint];
  preTransactionLeftSibling?: bigint;
  outputUtxos: Utxo[];
  viewingKeyRegistered?: boolean;
  merkleTree?: MerkleTree;
  addressLookupTableAccounts?: AddressLookupTableAccount[];
}
```

`swapUtxo` and `swapWithChange` both resolve to a `UtxoSwapResult`, which extends it:

```typescript
interface UtxoSwapResult extends TransactResult {
  swapStatePda: string;
  nullifier: string;
  requestId?: string;
  refund: {
    privateKey: string;
    publicKey: string;
    blinding: string;
    derivedFromNk: boolean;
  };
}
```

Persist `refund`. It is the recovery secret for reclaiming the input if the swap times out
before its second transaction lands.

## Fee constants

Fees are enforced on-chain from each pool's `PoolConfig`; `transact` reads the live config before
building a fee-bearing proof. These constants mirror the deployed SOL-pool defaults for display
math. SPL pools (USDC/USDT) charge `450_000` base units fixed (0.45) + 0.3%; see
[Fee Model](/protocol/fee-model).

```typescript
FIXED_FEE_LAMPORTS       // 5_000_000
VARIABLE_FEE_NUMERATOR   // 3
VARIABLE_FEE_DENOMINATOR // 1000
VARIABLE_FEE_RATE        // 0.003
MIN_DEPOSIT_LAMPORTS     // 10_000_000
LAMPORTS_PER_SOL         // 1_000_000_000

calculateFee(amountLamports: number)
calculateFeeBigint(amountLamports: bigint)
isWithdrawAmountSufficient(amountLamports: bigint)
getDistributableAmount(amountLamports: number)
formatAmount(lamports: number, decimals?: number)
parseAmount(sol: string)
```

These values cover the native SOL pool. SPL pools (USDC and USDT) charge a fixed 0.45 token,
450,000 raw units at 6 decimals, plus the same 0.3 percent variable fee. The program reads the
effective values from the `pool_config` PDA; the SDK does not compute SPL fees.

## Request authentication and endpoint pinning

Private sends, withdrawals and swaps carry a signed sender. Standard integrations only pass
`signMessage` + `walletPublicKey` (browser) or `depositorKeypair` (server) in `TransactOptions` and
never touch these; they exist for callers driving submission themselves.

```typescript
buildRelayAuthPreimage(endpoint, programId, body, sender, nowSeconds?, fields?): RelayAuthPreimage
canonicalJson(value: unknown): string
explainRelayAuthRejection(responseText: string): string | null
submitTransactToRelay(args: SubmitTransactToRelayArgs)

RelayAuthPreimage; // { sender, auth_issued_at, auth_nonce, message }
RelayAuthSigner; // { walletPublicKey, signMessage }, the end user's own wallet

TRANSACT_AUTH_FIELDS; // 9 fields, sorted; order is part of the agreement
TRANSACT_SWAP_AUTH_FIELDS; // 19 fields, sorted; `slippage_bps` must always be present

REQUEST_AUTH_MAX_AGE_SECONDS; // 300 (285 usable after the SDK's transit margin)
REQUEST_AUTH_MAX_FUTURE_SKEW_SECONDS; // 30

CLOAK_PRODUCTION_RELAY_URL; // name of the production endpoint, never a default
RELAY_ORIGIN_ALLOWLIST; // origins this build may reach; pinned at build time
BUILD_ALLOWS_LOCAL_ENDPOINTS; // derived: true only for a local build
```

`maxWalletApprovals` on `TransactOptions` caps wallet dialogs for one swap (default `5`). Sends and
withdrawals sign exactly once. Full contract: [Request authentication](/sdk/request-authentication).
