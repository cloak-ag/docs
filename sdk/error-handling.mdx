## SDK error surfaces

`@cloak.dev/sdk` exposes two main layers:

1. `CloakError` (runtime SDK operations)
2. `parseError` / `parseTransactionError` (user-facing normalization)

## `CloakError`

```typescript
import { CloakError } from "@cloak.dev/sdk";

// category values:
// "network" | "indexer" | "prover" | "relay" | "validation" | "wallet" | "environment" | "service"
```

Most app flows should treat `retryable === true` as backoff-eligible.

## Persist the change note before you report success

`transact`, `transfer`, `partialWithdraw`, `swapUtxo` and `swapWithChange` all return
`result.outputUtxos`, and the change note among them is the user's remaining shielded balance. Its
`blinding` is fresh randomness generated inside the SDK and is written nowhere on chain, so a change
note whose only copy you dropped is unspendable by anyone, permanently. No rescan brings it back.
Outputs with `amount === 0n` are padding and can be skipped. `fullWithdraw` leaves nothing shielded,
so it is the one call with no change note to keep.

This is an error-handling concern because every example below is a `try`/`catch`. The `catch` is the
failure path; the tail of the `try` is the success path, and that is where the write belongs. A
`try` block whose tail is empty has already lost the note by the time control reaches the next line.
`saveNotes` and `saveSwapRefund` in these snippets are your own storage, not SDK exports;
[Where your notes live between sessions](/sdk/wallet-integration#where-your-notes-live-between-sessions)
covers what to build them on.

## `Unauthorized` and bare `401` on a send, withdraw or swap

Every request Cloak submits for you carries a signed sender, and every way that can go wrong arrives
as the same opaque rejection. `explainRelayAuthRejection` turns one into user-facing prose, and
returns `null` for anything that is not an authentication rejection, so it is safe to call
unconditionally:

```typescript
import { explainRelayAuthRejection, fullWithdraw, parseError } from "@cloak.dev/sdk";

try {
  await fullWithdraw(inputUtxos, recipient, options);
} catch (error) {
  const hint = explainRelayAuthRejection(String(error));
  // Non-null examples: a wallet approval that sat past the 285-second budget, a machine
  // clock more than 30 seconds fast, a body that changed after it was signed, a wallet
  // with no viewing key registered yet.
  showError(hint ?? parseError(error).message);
}
```

Two of the causes are not a bug in your code at all: an approval dialog left waiting, and a wrong
clock on the user's machine. Both are recoverable by retrying, and in both cases nothing was
submitted. The full contract, including how to supply a signer at all, is in
[Request authentication](/sdk/request-authentication).

## Stale Merkle root (`0x1001`)

Use helpers for RootNotFound detection:

<CodeGroup>
```typescript Keypair bytes
import { fullWithdraw, isRootNotFoundError, RootNotFoundError } from "@cloak.dev/sdk";

try {
  await fullWithdraw(inputUtxos, recipient, {
    connection,
    programId,
    relayUrl,
    depositorKeypair,
    walletPublicKey: depositorKeypair.publicKey,
  });
  // fullWithdraw leaves nothing shielded, so there is no change note to persist here.
  // Every other flow has one: see the wallet-adapter tab.
} catch (error) {
  if (error instanceof RootNotFoundError || isRootNotFoundError(error)) {
    // Refresh proof inputs and retry flow
  }
}
```

```typescript Wallet adapter
import {
  isRootNotFoundError,
  partialWithdraw,
  RootNotFoundError,
  serializeUtxo,
} from "@cloak.dev/sdk";

try {
  const withdrawn = await partialWithdraw(inputUtxos, recipient, 10_000_000n, {
    connection,
    programId,
    relayUrl,
    walletPublicKey: publicKey!,
    signMessage: signMessage!,
  });
  // Success path: the remaining balance is here and nowhere else. Write it first.
  await saveNotes(
    withdrawn.outputUtxos.filter((utxo) => utxo.amount > 0n).map(serializeUtxo),
  );
} catch (error) {
  if (error instanceof RootNotFoundError || isRootNotFoundError(error)) {
    // Rebuild with fresh commitments/root and retry
  }
}
```

</CodeGroup>

SDK note and UTXO flows already include retry loops; this usually appears only after retries are exhausted.

## On-chain error message mapping

`ShieldPoolErrors` maps known custom program codes:

```typescript
import { ShieldPoolErrors } from "@cloak.dev/sdk";

console.log(ShieldPoolErrors[0x1001]); // Root not found in the roots ring
console.log(ShieldPoolErrors[0x1076]); // Proof verification failed
```

## User-facing normalization

<CodeGroup>
```typescript Keypair bytes
import {
  parseError,
  serializeUtxo,
  swapWithChange,
  type UserFriendlyError,
} from "@cloak.dev/sdk";

try {
  const swapped = await swapWithChange(
    inputUtxos,
    amountLamports,
    outputMint,
    recipientAta,
    minOutput,
    {
      connection,
      programId,
      relayUrl,
      depositorKeypair,
      walletPublicKey: depositorKeypair.publicKey,
    },
  );
  // Success path, two writes. The change note is the remaining shielded balance.
  await saveNotes(
    swapped.outputUtxos.filter((utxo) => utxo.amount > 0n).map(serializeUtxo),
  );
  // `swapped.refund` reclaims the principal if the swap times out before it executes.
  // With `chainNoteViewingKeyNk` supplied it can be rebuilt later via `discoverSwapRefunds`,
  // so saving it is the fast path. Without one, `refund.derivedFromNk` is false and this
  // object is the only copy that will ever exist.
  await saveSwapRefund(swapped.swapStatePda, swapped.refund);
} catch (error) {
  const parsed: UserFriendlyError = parseError(error);
  // parsed.category: wallet | network | validation | service | transaction | unknown
  // parsed.recoverable: boolean
}
```

```typescript Wallet adapter
import {
  parseError,
  serializeUtxo,
  swapWithChange,
  type UserFriendlyError,
} from "@cloak.dev/sdk";

  await saveSwapRefund(swapped.swapStatePda, swapped.refund);
} catch (error) {
  const parsed: UserFriendlyError = parseError(error);
  // parsed.category / parsed.recoverable
}
```

</CodeGroup>

## Practical retry strategy

- Retry network and service failures with exponential backoff.
- Avoid retrying deterministic validation failures.
- On stale-root errors, rebuild proof data before retrying.

## UTXO stale-root retry template

```typescript
import { isRootNotFoundError, partialWithdraw, serializeUtxo } from "@cloak.dev/sdk";

let result: Awaited<ReturnType<typeof partialWithdraw>> | undefined;
let cachedMerkleTree = initialMerkleTree;

for (let attempt = 1; attempt <= 3; attempt += 1) {
  try {
    result = await partialWithdraw(inputUtxos, recipientWallet, 10_000_000n, {
      connection,
      programId,
      relayUrl,
      walletPublicKey,
      signMessage,
      cachedMerkleTree,
    });
    break;
  } catch (error) {
    if (!isRootNotFoundError(error) || attempt === 3) throw error;
    await new Promise((resolve) => setTimeout(resolve, 1_500 * attempt));
    // refresh proof inputs before retrying (new root + updated tree)
    cachedMerkleTree = undefined;
  }
}

if (!result) throw new Error("withdraw did not complete");

// `break` only ends the retry. The change note is still unsaved at this point, and it is the
// only copy of the user's remaining balance, so persist it before anything reports success.
await saveNotes(result.outputUtxos.filter((utxo) => utxo.amount > 0n).map(serializeUtxo));
```

Swap `partialWithdraw` for `transact`, `transfer`, `swapUtxo` or `swapWithChange` and the loop is
unchanged, but the tail still has to run: each of those returns a change note too, and the two swap
helpers add a `refund` secret. `fullWithdraw` is the only substitution that needs no tail, because
it leaves nothing shielded.

## Security logging rule

Never log full notes/UTXOs with secrets. Log only non-sensitive identifiers (commitment prefix, leaf index, request ID, and tx signature when needed for support).
