This page is written against `@cloak.dev/sdk` 0.2.11. Catch the typed errors below instead of
matching message strings: the classes are the stable surface, the wording is not.

## SDK error surfaces

`@cloak.dev/sdk` exposes three layers:

1. `CloakError` (runtime SDK operations, with a `category` and a `retryable` flag)
2. Typed errors for the outcomes a caller must act on: `RootNotFoundError`,
   `UtxoAlreadySpentError`, `SanctionsQuoteError`, `RelayInternalError`,
   `SettlementVerificationError`, `TransactionConfirmationError`
3. `parseError` / `parseTransactionError` (user-facing normalization)

## `CloakError`

```ts
import { CloakError } from "@cloak.dev/sdk";

declare function run(): Promise<void>;

async function withBackoff(attempt: () => Promise<void>): Promise<void> {
  try {
    await attempt();
  } catch (error) {
    if (error instanceof CloakError) {
      // category: "network" | "indexer" | "prover" | "relay" | "validation" | "wallet"
      //         | "environment" | "service"
      console.log(error.category, error.retryable);
    }
    throw error;
  }
}

await withBackoff(run);
```

Most app flows should treat `retryable === true` as backoff-eligible.

## Typed errors

```ts
import {
  RelayInternalError,
  SanctionsQuoteError,
  SettlementVerificationError,
  TransactionConfirmationError,
  UtxoAlreadySpentError,
  fullWithdraw,
  type SpendOptions,
  type Utxo,
} from "@cloak.dev/sdk";
import type { Address } from "@solana/kit";

declare const inputUtxos: Utxo[];
declare const recipient: Address;
declare const options: SpendOptions;

try {
  await fullWithdraw(inputUtxos, recipient, options);
} catch (error) {
  if (error instanceof UtxoAlreadySpentError) {
    // A note was spent elsewhere. error.spentUtxoCommitments lists them; reconcile with verifyUtxos.
  } else if (error instanceof SettlementVerificationError) {
    // The relay never gave a usable answer. error.outcome says what chain state supports:
    //   "landed"     the transaction DID land: never retry, rescan to recover notes
    //   "not-landed" nothing landed: retrying is safe (error.safeToRetry)
    //   "unknown"    look up error.signature on an independent RPC before doing anything
    //   "failed"     on chain and failed during execution: inputs are unspent
    console.log(error.outcome, error.signature, error.reason);
  } else if (error instanceof SanctionsQuoteError) {
    // Structural mismatch between the quote and the program (error.subKind:
    // "expired" | "wallet_mismatch" | "missing_ix", error.onChainCode is the program code).
    // These are not something the caller can fix: they point to version skew or config drift
    // between the quote and the program. Report them.
  } else if (error instanceof TransactionConfirmationError) {
    // A direct (self-signed) transaction did not confirm. error.reason: "failed" | "expired" | "timeout".
    console.log(error.signature, error.reason);
  } else if (error instanceof RelayInternalError) {
    // A relay 5xx that maps to nothing more specific. Keep error.relayMessage for support.
    console.log(error.httpStatus, error.relayMessage);
  } else {
    throw error;
  }
}
```

`confirmTransactSettlement` re-checks a signature from chain state when an outcome was reported as
unknown.

## Persist the notes before you report success

`transact`, `transfer`, `partialWithdraw`, `swapUtxo` and `swapWithChange` all return
`result.outputUtxos`, and the change note among them is the user's remaining shielded balance.
Outputs with `amount === 0n` are padding and can be skipped. `fullWithdraw` leaves nothing shielded.

The notes the SDK builds for you are derived from your `nk` and a salt published in the encrypted
chain note, so a lost change note can be found again by a scan (`recoverNotesFromIndex`,
`scanTransactions`). Writing it down is still the fast path and gives you the leaf index at once.
The notes that cannot be found again are the ones you built yourself with `createUtxo`, whose
`blinding` is random and written nowhere, and notes owned by a random `generateUtxoKeypair()` key you
did not keep. Those are unspendable by anyone if the only copy is dropped.

This is an error-handling concern because every example below is a `try`/`catch`. The `catch` is the
failure path; the tail of the `try` is the success path, and that is where the write belongs.
`saveNotes`, `dropNotes` and `saveSwapRefund` in these snippets are your own storage, not SDK
exports; [Where your notes live between sessions](/sdk/wallet-integration#where-your-notes-live-between-sessions)
covers what to build them on.

## When `fullWithdraw` merges first

The circuit spends at most two notes per transaction, so both `fullWithdraw` and `partialWithdraw`
consolidate first when you pass three or more inputs. Each consolidation round is its own on-chain
transaction: it spends the two smallest notes and creates one merged note owned by your
`ownerUtxoKeypair`. `onProgress` fires `Consolidating notes (n remaining)...` once per round, and
that string is the signal a caller gets that consolidation is happening at all.

Rounds that land are permanent, and the failure is what makes this an error-handling problem. If a
later round or the final withdrawal throws (stale-root retries exhausted, a rejected wallet approval,
a submission failure, a closed tab), then the two notes that round consumed are spent, the merged
commitment is in the tree, and the call returned nothing, so there is no `result.outputUtxos` to
write down.

The merged note is not destroyed. Its blinding is derived from your `nk` and a salt the round
published in its chain note, so a rescan finds it again. Until you rescan, though, your app does not
know it exists, and retrying with the original `inputUtxos` fails: the first merge round preflights
their nullifiers and throws `UtxoAlreadySpentError`.

What you can actually do, in order of usefulness:

<CodeGroup>
```ts Consolidate yourself first
import {
  createRecoverableChangeUtxo,
  fullWithdraw,
  randomChangeNoteSalt,
  serializeUtxo,
  transact,
  type SpendOptions,
  type Utxo,
} from "@cloak.dev/sdk";
import type { Address } from "@solana/kit";

declare const inputUtxos: Utxo[];
declare const recipient: Address;
declare const options: SpendOptions; // includes ownerUtxoKeypair and chainNoteViewingKeyNk
declare const nk: Uint8Array; // the same nk as options.chainNoteViewingKeyNk
declare function saveNotes(notes: Uint8Array[]): Promise<void>;

// Each merge is now your transaction: it returns, and you persist, before the next one starts.
let notes = [...inputUtxos];
while (notes.length > 2) {
  notes.sort((a, b) => (a.amount > b.amount ? 1 : a.amount < b.amount ? -1 : 0));
  const [small1, small2, ...rest] = notes;
  const salt = randomChangeNoteSalt();
  const { utxo: merged } = await createRecoverableChangeUtxo(
    small1.amount + small2.amount,
    options.ownerUtxoKeypair,
    nk,
    small1.mintAddress,
    salt,
    0,
  );
  const result = await transact(
    { inputUtxos: [small1, small2], outputUtxos: [merged], externalAmount: 0n },
    { ...options, chainNoteSalt: salt },
  );
  // The merged note exists on chain now. Write it before the next round can fail.
  await saveNotes(result.outputUtxos.filter((utxo) => utxo.amount > 0n).map(serializeUtxo));
  notes = [result.outputUtxos[0], ...rest];
}

// Two notes left, so this call performs no merges.
await fullWithdraw(notes, recipient, options);
```

```ts Reconcile after a throw
import { fullWithdraw, verifyUtxos, type SpendOptions, type Utxo } from "@cloak.dev/sdk";
import type { Address } from "@solana/kit";

declare const inputUtxos: Utxo[];
declare const recipient: Address;
declare const options: SpendOptions;
declare function dropNotes(commitments: bigint[]): Promise<void>;

let consolidated = false;
try {
  await fullWithdraw(inputUtxos, recipient, {
    ...options,
    onProgress: (status) => {
      if (status.startsWith("Consolidating notes")) consolidated = true;
    },
  });
} catch (error) {
  if (consolidated) {
    // Some inputs are spent and one merged note is not in your store. Never retry with
    // `inputUtxos`: the first merge round preflights the nullifiers and throws
    // `UtxoAlreadySpentError` (0x1020).
    const { spent, unspent } = await verifyUtxos(inputUtxos, options.connection, options.programId);
    // Anything without a commitment lands in `skipped`, so `spent` entries always have one.
    await dropNotes(spent.map((utxo) => utxo.commitment!));
    // Rescan with recoverNotesFromIndex to pick up the merged note, then withdraw again from it
    // and from `unspent`. If the withdrawal itself landed and only its confirmation failed, the
    // recipient already has the funds, so check their balance first.
    console.log(unspent.length);
  }
  throw error;
}
```

</CodeGroup>

Consolidating yourself is the only option that prevents the gap rather than recovering from it.
Prefer it in any flow where the user can hold more than two notes.

## `Unauthorized` and bare `401` on a send, withdraw or swap

Every request Cloak submits for you carries a signed sender, and every way that can go wrong arrives
as the same opaque rejection. `explainRelayAuthRejection` turns one into user-facing prose, and
returns `null` for anything that is not an authentication rejection, so it is safe to call
unconditionally:

```ts
import {
  explainRelayAuthRejection,
  fullWithdraw,
  parseError,
  type SpendOptions,
  type Utxo,
} from "@cloak.dev/sdk";
import type { Address } from "@solana/kit";

declare const inputUtxos: Utxo[];
declare const recipient: Address;
declare const options: SpendOptions;
declare function showError(message: string): void;

try {
  await fullWithdraw(inputUtxos, recipient, options);
} catch (error) {
  const hint = explainRelayAuthRejection(String(error));
  // Non-null examples: a wallet approval that sat past the 300-second window, a machine
  // clock more than 30 seconds fast, a body that changed after it was signed, a wallet
  // with no viewing key registered yet.
  showError(hint ?? parseError(error).message);
}
```

Two of the causes are not a bug in your code at all: an approval dialog left waiting, and a wrong
clock on the user's machine. Both are recoverable by retrying, and nothing was submitted for the
request that was rejected. That is not the same as nothing having been submitted: with three or more
inputs the rejection can arrive on a round that follows landed consolidation transactions, so
reconcile with `verifyUtxos` before retrying rather than reusing `inputUtxos`. The full contract,
including how to supply a signer at all, is in
[Request authentication](/sdk/request-authentication).

A call that has no usable signer never reaches the network. It throws up front, before any proof is
generated, with a message that begins `Cloak <flow> requires an authenticated sender` (for a
transfer, withdrawal or swap), `<flow> requires options.ownerUtxoKeypair` (a spend flow with no
owner key), or `Viewing key registration is mandatory` (no `nk`, or nothing to sign the registration
challenge). Those are setup mistakes, not runtime failures: fix the options rather than catching them.

## Stale Merkle root (`0x1001`)

Use helpers for RootNotFound detection:

<CodeGroup>
```ts Keypair bytes
import {
  fullWithdraw,
  isRootNotFoundError,
  RootNotFoundError,
  type SpendOptions,
  type Utxo,
} from "@cloak.dev/sdk";
import type { Address } from "@solana/kit";

declare const inputUtxos: Utxo[];
declare const recipient: Address;
declare const options: SpendOptions; // built with depositorKeypair, ownerUtxoKeypair and nk

try {
  await fullWithdraw(inputUtxos, recipient, options);
  // With one or two inputs this leaves nothing shielded, so there is no change note to
  // persist here. With three or more, consolidation runs first: see "When fullWithdraw merges
  // first". Every other flow has a change note either way.
} catch (error) {
  if (error instanceof RootNotFoundError || isRootNotFoundError(error)) {
    // Refresh proof inputs, then reconcile with verifyUtxos before retrying: a stale root on
    // the final withdrawal can follow consolidation rounds that already landed.
  }
}
```

```ts Wallet adapter
import {
  isRootNotFoundError,
  partialWithdraw,
  RootNotFoundError,
  serializeUtxo,
  type SpendOptions,
  type Utxo,
} from "@cloak.dev/sdk";
import type { Address } from "@solana/kit";

declare const inputUtxos: Utxo[];
declare const recipient: Address;
declare const walletOptions: SpendOptions; // built with walletPublicKey, signMessage, ownerUtxoKeypair and nk
declare function saveNotes(notes: Uint8Array[]): Promise<void>;

try {
  const withdrawn = await partialWithdraw(inputUtxos, recipient, 10_000_000n, walletOptions);
  // Success path: write the remaining balance down now.
  await saveNotes(
    withdrawn.outputUtxos.filter((utxo) => utxo.amount > 0n).map(serializeUtxo),
  );
} catch (error) {
  if (error instanceof RootNotFoundError || isRootNotFoundError(error)) {
    // Rebuild with fresh commitments/root and retry
  }
}
```

</CodeGroup>

SDK note and UTXO flows already include retry loops (`maxRootRetries`); this usually appears only
after retries are exhausted.

## On-chain error message mapping

`ShieldPoolErrors` maps known custom program codes:

```ts
import { ShieldPoolErrors } from "@cloak.dev/sdk";

console.log(ShieldPoolErrors[0x1001]); // Root not found in the roots ring
console.log(ShieldPoolErrors[0x1020]); // Double spend detected - this note has already been spent
console.log(ShieldPoolErrors[0x1076]); // Proof verification failed
```

## User-facing normalization

<CodeGroup>
```ts Keypair bytes
import {
  parseError,
  serializeUtxo,
  swapWithChange,
  type SpendOptions,
  type UserFriendlyError,
  type Utxo,
  type UtxoSwapResult,
} from "@cloak.dev/sdk";
import type { Address } from "@solana/kit";

declare const inputUtxos: Utxo[];
declare const amountLamports: bigint;
declare const outputMint: Address;
declare const recipientAta: Address;
declare const recipientWallet: Address;
declare const minOutput: bigint;
declare const options: SpendOptions; // depositorKeypair, ownerUtxoKeypair, chainNoteViewingKeyNk
declare function saveNotes(notes: Uint8Array[]): Promise<void>;
declare function saveSwapRefund(
  swapStatePda: string,
  refund: UtxoSwapResult["refund"],
): Promise<void>;

try {
  const swapped = await swapWithChange(
    inputUtxos,
    amountLamports,
    outputMint,
    recipientAta,
    minOutput,
    options,
    recipientWallet,
  );
  // Success path, two writes. The change note is the remaining shielded balance.
  await saveNotes(
    swapped.outputUtxos.filter((utxo) => utxo.amount > 0n).map(serializeUtxo),
  );
  // `swapped.refund` reclaims the principal if the swap times out before it executes.
  // With `chainNoteViewingKeyNk` supplied it can be rebuilt later via `discoverSwapRefunds`
  // (`refund.derivedFromNk` is true), so saving it is the fast path.
  await saveSwapRefund(swapped.swapStatePda, swapped.refund);
} catch (error) {
  const parsed: UserFriendlyError = parseError(error);
  // parsed.category: wallet | network | validation | service | transaction | unknown
  // parsed.recoverable: boolean
  console.log(parsed.title, parsed.message, parsed.suggestion);
}
```

## Practical retry strategy

- Retry network and service failures with exponential backoff.
- Avoid retrying deterministic validation failures.
- On stale-root errors, rebuild proof data before retrying.
- Never retry a `SettlementVerificationError` whose `outcome` is not `"not-landed"`.

## UTXO stale-root retry template

`transact`, `partialWithdraw` and `fullWithdraw` already retry a stale root internally, so an outer
loop is only for the case where those retries are exhausted:

```ts
import {
  isRootNotFoundError,
  partialWithdraw,
  serializeUtxo,
  type MerkleTree,
  type SpendOptions,
  type Utxo,
} from "@cloak.dev/sdk";
import type { Address } from "@solana/kit";

declare const inputUtxos: Utxo[]; // one or two notes
declare const recipientWallet: Address;
declare const options: SpendOptions;
declare const initialMerkleTree: MerkleTree | undefined;
declare function saveNotes(notes: Uint8Array[]): Promise<void>;

let result: Awaited<ReturnType<typeof partialWithdraw>> | undefined;
let cachedMerkleTree = initialMerkleTree;

for (let attempt = 1; attempt <= 3; attempt += 1) {
  try {
    result = await partialWithdraw(inputUtxos, recipientWallet, 10_000_000n, {
      ...options,
      cachedMerkleTree,
    });
    break;
  } catch (error) {
    if (!isRootNotFoundError(error) || attempt === 3) throw error;
    await new Promise((resolve) => setTimeout(resolve, 1_500 * attempt));
    // refresh proof inputs before retrying (new root + updated tree)
    cachedMerkleTree = undefined;
  }
}

if (!result) throw new Error("withdraw did not complete");

// `break` only ends the retry. The change note is still unsaved at this point, so persist it
// before anything reports success.
await saveNotes(result.outputUtxos.filter((utxo) => utxo.amount > 0n).map(serializeUtxo));
```

This template reuses `inputUtxos` on every attempt, which is safe only while that array holds one or
two notes. With three or more, attempt 1 can land consolidation transactions before it throws, and
attempt 2 then spends notes that are already nullified: the first merge round preflights them and
throws `UtxoAlreadySpentError` instead of retrying. Consolidate down to two notes yourself before
entering a loop like this, as in
[When `fullWithdraw` merges first](#when-fullwithdraw-merges-first).

Swap `partialWithdraw` for `transact`, `transfer`, `swapUtxo` or `swapWithChange` and the loop is
unchanged, but the tail still has to run: each of those returns a change note too, and the two swap
helpers add a `refund` authorization. `fullWithdraw` is the only substitution that can skip the
tail, and only when it is given one or two notes, because that is when it leaves nothing shielded
and performs no merges of its own.

## Security logging rule

Never log full notes/UTXOs with secrets. Log only non-sensitive identifiers (commitment prefix, leaf index, request ID, and tx signature when needed for support).
