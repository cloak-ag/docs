If your app stack is built around `@solana/kit`, you can still use Cloak SDK today.

Current state:

- Use Kit for RPC reads, subscriptions, and signer architecture.
- Use a thin `@solana/web3.js` bridge for Cloak transaction calls (`transact`, `partialWithdraw`, `swapWithChange`, etc.).

## Which half of this page is yours

Kit apps come in two shapes, and they diverge at the first flow that is submitted for you. A
deposit is signed by the funding wallet and posted directly. A private send, a withdrawal or a swap
is submitted on your behalf, and each of those requests carries an authenticated sender signed by
the end user's own wallet.

| Your Kit app runs in | Signer you have | Cloak options you pass |
|---|---|---|
| A browser, with `@solana/wallet-adapter-react` | no secret key, only `signTransaction` and `signMessage` | `signTransaction` + `depositorPublicKey` for the deposit, `signMessage` + `walletPublicKey` for everything after |
| A server, a script or a CLI | a local `Keypair` | `depositorKeypair` |

<Warning>
**Most Kit stacks are frontends, and a frontend cannot use `depositorKeypair`.** It takes a secret
key that a browser wallet never releases. If your Kit app runs in a browser, skip the keypair
example below and use the wallet-adapter one. The full contract, including the approval window and
how many prompts to expect, is [Request authentication](/sdk/request-authentication).
</Warning>

## Install

```bash
npm install @cloak.dev/sdk @solana/web3.js @solana/kit
```

Browser apps add the wallet adapter:

```bash
npm install @solana/wallet-adapter-react
```

## The endpoint value

The submission endpoint is pinned when the SDK is built, and **the SDK reads no environment
variable for it**. Pass the exported constant rather than a host you typed or a value you read from
the environment:

```typescript
import { CLOAK_PRODUCTION_RELAY_URL } from "@cloak.dev/sdk";

const relayUrl = CLOAK_PRODUCTION_RELAY_URL;
```

`CLOAK_RELAY_URL` is a convention that the SDK's own examples and scripts read themselves and pass
in as `relayUrl`. If your Kit app does the same, it is your code doing the reading, and the value
still has to be an origin on this build's allowlist or the call throws. There is no default:
omitting `relayUrl` yields `undefined`, never production.

<Warning>
Omitting `relayUrl`, or passing `""`, makes every flow **including deposits** throw
`Viewing key registration is mandatory: relayUrl is required.` before any network call. `""` is the
caller-signed direct-submission signal, but it only takes effect when
`enforceViewingKeyRegistration` is also set to `false`, because the viewing-key gate fires first.
That pair is not a frontend recipe: with a signer present it submits a transfer or withdrawal under
the user's own key, publicly linking it.
</Warning>

To point a Kit app at a local stack, edit the allowlist and rebuild the SDK. See
[Developing against a local stack](/sdk/request-authentication#developing-against-a-local-stack).

## Bridge pattern: browser Kit app

Kit reads balances. The web3.js `Connection` is the bridge Cloak calls take. The wallet supplies
both signatures and no secret key ever exists in your app.

```tsx
import {
  CLOAK_PRODUCTION_RELAY_URL,
  CLOAK_PROGRAM_ID,
  NATIVE_SOL_MINT,
  createUtxo,
  createZeroUtxo,
  explainRelayAuthRejection,
  generateUtxoKeypair,
  partialWithdraw,
  transact,
} from "@cloak.dev/sdk";
import { address, createSolanaRpc } from "@solana/kit";
import { useWallet } from "@solana/wallet-adapter-react";
import { Connection, PublicKey } from "@solana/web3.js";

const rpcUrl = process.env.NEXT_PUBLIC_SOLANA_RPC_URL!;
const relayUrl = CLOAK_PRODUCTION_RELAY_URL;
const programId = CLOAK_PROGRAM_ID;

// Kit client for read paths.
const kitRpc = createSolanaRpc(rpcUrl);

// web3 bridge for Cloak transaction paths.
const connection = new Connection(rpcUrl, "confirmed");

export function useCloakBridge() {
  const { publicKey, signTransaction, signMessage } = useWallet();

  return async function depositThenWithdraw(recipientAddress: string) {
    // Not every adapter implements signMessage. Check before you offer the action, so the
    // user is never asked to prove and then told their wallet cannot sign the request.
    if (!publicKey || !signTransaction || !signMessage) {
      throw new Error("Connect a wallet that supports message signing.");
    }

    const { value: before } = await kitRpc
      .getBalance(address(publicKey.toBase58()))
      .send();

    const owner = await generateUtxoKeypair();
    const output = await createUtxo(20_000_000n, owner, NATIVE_SOL_MINT);

    const deposit = await transact(
      {
        inputUtxos: [await createZeroUtxo(NATIVE_SOL_MINT)],
        outputUtxos: [output],
        externalAmount: 20_000_000n,
        depositor: publicKey,
      },
      {
        connection,
        programId,
        relayUrl,
        signTransaction, // wallet signs the deposit transaction
        signMessage, // authenticates viewing-key registration and every later request
        depositorPublicKey: publicKey,
        walletPublicKey: publicKey, // same key; becomes the authenticated sender
        onProofProgress: (percent) => console.log(`deposit proof ${percent}%`),
      },
    );

    try {
      await partialWithdraw(
        deposit.outputUtxos,
        new PublicKey(recipientAddress),
        10_000_000n,
        {
          connection,
          programId,
          relayUrl,
          walletPublicKey: publicKey, // the request's authenticated sender
          signMessage, // signs the request preimage
          cachedMerkleTree: deposit.merkleTree,
          onProofProgress: (percent) => console.log(`withdraw proof ${percent}%`),
        },
      );
    } catch (error) {
      const hint = explainRelayAuthRejection(String(error));
      throw hint ? new Error(hint, { cause: error }) : error;
    }

    const { value: after } = await kitRpc
      .getBalance(address(publicKey.toBase58()))
      .send();
    console.log(before.toString(), after.toString());
  };
}
```

<Note>
`walletPublicKey` must be the end user's own wallet, never an ephemeral or service-held key. It
becomes the request's sender, the key that is screened, and the key a viewing key is registered
against. A private send or a withdrawal prompts **exactly once**, including across stale-root
retries.
</Note>

## Bridge pattern: server or CLI Kit app

Same bridge, with a local keypair in place of the two wallet callbacks. Use this only where the
process legitimately holds the key.

```typescript
import {
  CLOAK_PRODUCTION_RELAY_URL,
  CLOAK_PROGRAM_ID,
  NATIVE_SOL_MINT,
  createUtxo,
  createZeroUtxo,
  generateUtxoKeypair,
  partialWithdraw,
  transact,
} from "@cloak.dev/sdk";
import { address, createSolanaRpc } from "@solana/kit";
import { Connection, Keypair } from "@solana/web3.js";
import { readFileSync } from "node:fs";

const rpcUrl = process.env.SOLANA_RPC_URL!;
const relayUrl = CLOAK_PRODUCTION_RELAY_URL;
const programId = CLOAK_PROGRAM_ID;

const kitRpc = createSolanaRpc(rpcUrl);
const connection = new Connection(rpcUrl, "confirmed");
const signer = Keypair.fromSecretKey(
  Uint8Array.from(JSON.parse(readFileSync(process.env.KEYPAIR_PATH!, "utf8"))),
);

const { value: before } = await kitRpc
  .getBalance(address(signer.publicKey.toBase58()))
  .send();

const owner = await generateUtxoKeypair();
const output = await createUtxo(20_000_000n, owner, NATIVE_SOL_MINT);

const deposit = await transact(
  {
    inputUtxos: [await createZeroUtxo(NATIVE_SOL_MINT)],
    outputUtxos: [output],
    externalAmount: 20_000_000n,
    depositor: signer.publicKey,
  },
  {
    connection,
    programId,
    relayUrl,
    depositorKeypair: signer,
  },
);

await partialWithdraw(
  deposit.outputUtxos,
  Keypair.generate().publicKey,
  10_000_000n,
  {
    connection,
    programId,
    relayUrl,
    depositorKeypair: signer,
    walletPublicKey: signer.publicKey,
    cachedMerkleTree: deposit.merkleTree,
  },
);

const { value: after } = await kitRpc
  .getBalance(address(signer.publicKey.toBase58()))
  .send();
console.log(before.toString(), after.toString());
```

A keypair signs in microseconds and never prompts.
