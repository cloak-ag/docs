Since **0.2.5** the SDK is built on `@solana/kit`, so a Kit app needs no bridge at all. Cloak's own
types are Kit types:

- `connection` is a `CloakRpc` from `createCloakRpc(rpcUrl)`, not a web3.js `Connection`.
- `programId`, mints and recipients are Kit `Address` strings, not `PublicKey` instances.
- `depositorKeypair` is a Kit `KeyPairSigner`, and `signer` is a Kit transaction signer.

`@solana/web3.js` is now an optional peer dependency. The only thing that still needs it is the
browser wallet-adapter bridge, which hands the wallet a `VersionedTransaction` to sign.

## Which half of this page is yours

Kit apps come in two shapes, and they diverge at the first flow that is submitted for you. A
deposit is signed by the funding wallet and posted directly. A private send, a withdrawal or a swap
is submitted on your behalf, and each of those requests carries an authenticated sender signed by
the end user's own wallet.

| Your Kit app runs in | Signer you have | Cloak options you pass |
|---|---|---|
| A browser, with `@solana/wallet-adapter-react` | no secret key, only `signTransaction` and `signMessage` | `signTransaction` + `depositorPublicKey` for the deposit, `signMessage` + `walletPublicKey` for everything after |
| A server, a script or a CLI | a local secret key | `depositorKeypair` (a `KeyPairSigner`) |

<Warning>
**Most Kit stacks are frontends, and a frontend cannot use `depositorKeypair`.** It takes a secret
key that a browser wallet never releases. If your Kit app runs in a browser, skip the keypair
example below and use the wallet-adapter one. The full contract, including the approval window and
how many prompts to expect, is [Request authentication](/sdk/request-authentication).
</Warning>

## Install

```bash
npm install @cloak.dev/sdk @solana/kit
```

Browser apps add the wallet adapter and `@solana/web3.js`, which the adapter bridge needs:

```bash
npm install @solana/wallet-adapter-react @solana/web3.js
```

## The endpoint value

The submission endpoint is pinned when the SDK is built, and **the SDK reads no environment
variable for it**. Pass the exported constant rather than a host you typed or a value you read from
the environment:

```typescript
import { CLOAK_PRODUCTION_RELAY_URL } from "@cloak.dev/sdk";

const relayUrl = CLOAK_PRODUCTION_RELAY_URL;
```

`CLOAK_RELAY_URL` is a convention that the SDK's own examples and scripts read themselves and pass
in as `relayUrl`. If your Kit app does the same, it is your code doing the reading, and the value
still has to be an origin on this build's allowlist or the call throws. There is no default:
omitting `relayUrl` yields `undefined`, never production.

<Warning>
Omitting `relayUrl`, or passing `""`, makes every flow **including deposits** throw
`Viewing key registration is mandatory: relayUrl is required.` before any network call. `""` is the
caller-signed direct-submission signal, but it only takes effect when
`enforceViewingKeyRegistration` is also set to `false`, because the viewing-key gate fires first.
That pair is not a frontend recipe: with a signer present it submits a transfer or withdrawal under
the user's own key, publicly linking it.
</Warning>

To point a Kit app at a local stack, edit the allowlist and rebuild the SDK. See
[Developing against a local stack](/sdk/request-authentication#developing-against-a-local-stack).

## Wiring a browser Kit app

Wrap the connected wallet adapter with `signerFromWalletAdapter` and pass the result as `signer`.
No secret key ever exists in your app.

```tsx
import {
  CLOAK_PRODUCTION_RELAY_URL,
  CLOAK_PROGRAM_ID,
  createCloakRpc,
  signerFromWalletAdapter,
} from "@cloak.dev/sdk";
import { useWallet } from "@solana/wallet-adapter-react";
import { VersionedTransaction } from "@solana/web3.js";

const connection = createCloakRpc(process.env.NEXT_PUBLIC_SOLANA_RPC_URL!);

function useCloakOptions() {
  const wallet = useWallet();
  if (!wallet.publicKey) return null;

  // Pass your own VersionedTransaction: a bundler cannot resolve the bridge's on-demand import.
  const signer = signerFromWalletAdapter(wallet, { web3: { VersionedTransaction } });

  return {
    connection,
    programId: CLOAK_PROGRAM_ID,
    relayUrl: CLOAK_PRODUCTION_RELAY_URL,
    signer,
  };
}
```

`signerFromWalletAdapter` throws if the adapter has no `publicKey` (not connected). It always
provides transaction signing; it adds message signing only when the adapter exposes `signMessage`.
That matters because a wallet without `signMessage` authenticates requests by signing a
deterministic no-op transaction instead — the path a Ledger or Trezor takes. Either way the
authenticated sender must be the end user's own wallet, never an ephemeral or service-held key.

## Wiring a server or CLI Kit app

Load the secret key into a `KeyPairSigner` and pass it as `depositorKeypair`.

```typescript
import { readFileSync } from "node:fs";
import {
  CLOAK_PRODUCTION_RELAY_URL,
  CLOAK_PROGRAM_ID,
  createCloakRpc,
  signerFromSecretKey,
} from "@cloak.dev/sdk";

const connection = createCloakRpc(process.env.SOLANA_RPC_URL!);

const depositorKeypair = await signerFromSecretKey(
  Uint8Array.from(JSON.parse(readFileSync(process.env.KEY_FILE!, "utf8"))),
);

const options = {
  connection,
  programId: CLOAK_PROGRAM_ID,
  relayUrl: CLOAK_PRODUCTION_RELAY_URL,
  depositorKeypair,
};
```

`generateKeyPairSigner()` gives a throwaway signer for tests, and `signerFromKeypair({ secretKey })`
accepts an object that already carries raw secret-key bytes.

## Coming from web3.js

If you are upgrading an integration written against 0.2.2 or earlier:

| Before (≤ 0.2.4) | Now (0.2.5) |
|---|---|
| `new Connection(rpcUrl, "confirmed")` | `createCloakRpc(rpcUrl)` |
| `new PublicKey(value)` | `address(value)` |
| a web3.js `PublicKey` you already hold | `addressFromPublicKey(publicKey)` |
| `Keypair.fromSecretKey(bytes)` | `await signerFromSecretKey(bytes)` |
| `keypairToAdapter(keypair)` | removed — use a `KeyPairSigner` directly |
| `WalletAdapter` type | removed — use `LegacyWalletAdapter` with `signerFromWalletAdapter` |
