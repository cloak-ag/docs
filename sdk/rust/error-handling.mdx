The Rust SDK exposes a single `Error` enum with typed variants. The engine classifies RPC / relay responses into these variants internally so callers (and the retry loop) can match on them without string-sniffing.

## The `Error` enum

```rust
pub enum Error {
    Config(&'static str),
    Validation(&'static str),
    InsufficientFunds { available: u64, required: u64 },
    MissingUtxos,
    Storage(&'static str),
    Signer(&'static str),
    Crypto(&'static str),
    RootNotFound,
    BlockhashExpired,
    StaleProofState,
    Relay(&'static str),
}
```

### Classification

| Variant | Emitted when | Handled by |
|---|---|---|
| `Config` | Missing required option (rpc / payer / relay_url), dep setup issue, serialization failure | caller — fix the config |
| `Validation` | Preflight rejects inputs (bad arity, balance mismatch, min deposit, etc.) | caller — fix the params |
| `InsufficientFunds` | Surfaced by wallet-layer code composed on top of the engine (coin selection, balance checks). `transact()` itself validates balance at the circuit level via `Error::Validation`. | caller |
| `MissingUtxos` | Same — surfaced by wallet-layer code that selects inputs. | caller |
| `Signer` | Ed25519 signing failed on the v0 tx message | caller — check the keypair |
| `Crypto` | Poseidon / HKDF / AES-GCM failure | caller — usually a serialization bug |
| `RootNotFound` | Program error `0x1001` (proof root not in history) | retry loop — refresh tree |
| `BlockhashExpired` | RPC returned `BlockhashNotFound` / `TransactionExpiredBlockhashNotFound` | `submit_direct` — refresh + resign |
| `StaleProofState` | Circuit assertion failed (`ForceEqual*`, "invalid proof") | retry loop — force chain-indexing rebuild |
| `Relay` | Non-classified relay / RPC failure | caller — check `tracing::debug!` for body |

## Retry loops

Two loops run automatically; callers rarely need to retry themselves.

### Outer (transact-level)

Up to `opts.max_root_retries` (default 40) iterations. Mapped via `classify_iteration_error`:

- `RootNotFound` → drop `LoopState.tree_state` → refetch from RPC → re-prove
- `StaleProofState` → drop `LoopState.merkle_tree` + set `force_chain_indexing` → re-prove
- Any other → bubble up as `FatalError`

### Inner (submit_direct)

Wrapped around the signed-tx send:

- `BlockhashExpired` → refresh blockhash, recompile the v0 message, re-sign, re-send (up to 2 refreshes).
- `Relay(_)` → retry the same wire bytes with exponential backoff + jitter (up to 3 attempts, base 500 ms).
- `RootNotFound` → bubble up immediately for the outer loop.
- Anything else → bubble up.

Tune the backoff base with `opts.transport_backoff_base_ms` (set to 0 in tests).

## Matching errors in caller code

Most callers only need to distinguish "fatal" from "ask-again" cases:

```rust
// `let mut change_note = change_output.clone();` ran before `opts` moved into
// the call, so it holds the only copy of that output's blinding. `notes` is
// your `NoteStore` impl.
match transact(opts).await {
    Ok(result) => {
        // Persist first, before logging or returning `result`.
        change_note.index = result.output_indices[0]; // may be None; store anyway
        notes.insert(change_note)?;
        notes.mark_spent(&input_commitment_be)?;
    }
    Err(Error::Validation(msg)) => {
        eprintln!("bad request: {msg}");
    }
    Err(Error::Config(msg)) => {
        eprintln!("misconfigured: {msg}");
    }
    Err(Error::RootNotFound) => {
        // Only reached if max_root_retries was exhausted — unusually bad
        // relay or cluster state. Wait and retry.
    }
    Err(e) => {
        eprintln!("other: {e}");
    }
}
// Do not drop `change_note` on the error arms. See below.
```

Most `Error` variants are non-exhaustive-friendly (`#[non_exhaustive]` on the enum), so caller code should include a default arm.

## Errors and note persistence

An `Err` is not proof that nothing landed on chain. `submit_direct` refreshes the blockhash and re-sends, and retries a transient `Error::Relay` with the same signed bytes, so a transaction can confirm while the call still returns an error. Keep every output `Utxo` you built until you have checked the chain yourself. Discarding a note on an error arm is how a confirmed note becomes unspendable: the `blinding` exists nowhere but in that value, and no scan of the chain rebuilds it.

The expensive case is a **multi-note consolidation sequence**. The circuit takes 2 inputs, so a balance spread across three or more notes cannot be spent in one call. You merge first, one `transact()` per round, and every round is a real transaction that nullifies two notes on chain and creates a merged note whose blinding lives only in the `Utxo` you are holding. If round three fails, rounds one and two have already spent their inputs and the merged notes are the only claim on that balance.

So the rule is per round, not per sequence:

1. Clone the merged output before it moves into `TransactOptions.outputs`.
2. Call `transact()`.
3. Write `result.output_indices[0]` into the clone, `insert` it, and `mark_spent` the two consumed inputs.
4. Only then start the next round.

This is also why "this flow creates no note" is never a property of a whole withdrawal. A withdrawal that moves the entire remaining balance out has a zero-UTXO change output and nothing to store, but if you reached it by consolidating three notes into two, the rounds before it each produced a note that had to be stored. Judge storage per `transact()` call, never per user-level operation.

Recovering from a failure mid-sequence is straightforward if you followed the rule: the merged notes you stored are ordinary spendable notes. Resume from your store, not from the original input list, whose early notes are already spent.

## Debug tracing

Dynamic error bodies don't live inside the typed `Error` to keep the variant set stable. They're logged via `tracing` at `debug` level with `target = "cloak_sdk::relay"` or `target = "cloak_sdk::rpc"`:

```rust
use tracing_subscriber::{EnvFilter, FmtSubscriber};

FmtSubscriber::builder()
    .with_env_filter(EnvFilter::from_default_env())
    .init();
```

Run with `RUST_LOG=cloak_sdk=debug` to see the full RPC / relay bodies that led to each classification.

## Common failure modes

| Symptom | Cause | Fix |
|---|---|---|
| `Error::Config("direct submission requires opts.payer")` | No keypair on a deposit | Set `opts.payer = Some(Arc::new(keypair))` |
| `Error::Config("SPL direct withdraw is not supported")` | SPL withdraw via direct path | Use a relay (`opts.relay_url`) |
| `Error::Config("TransactSwap is relay-only")` | Swap without relay | Set `opts.relay_url` |
| `Error::Validation("balance mismatch")` | `inputs + external_amount != outputs` | Fix the UTXO amounts |
| `Error::Validation("transact exhausted max_root_retries")` | Outer loop gave up | Increase `max_root_retries` or investigate relay health. Keep the output notes you built ([why](#errors-and-note-persistence)) |
| `Error::Relay("swap execution failed")` | Status poll returned `failed` | Check `tracing` output for the relay error string |
| `Error::Relay("swap status: polling timed out")` | 60 polls × 2 s without resolution | Bump `opts.swap_status_max_attempts` |
| `Error::Crypto("circuit artifact hash mismatch")` | Corrupt cached zkey/wasm | Delete `~/Library/Caches/cloak-sdk/circuits/` and retry |
