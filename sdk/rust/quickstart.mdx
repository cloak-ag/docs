This walks through the smallest useful integration: a single-output SOL deposit submitted directly (user signs).

<Warning>
  **This crate cannot currently produce a proof the deployed program will accept.**
  `cloak-sdk` pins its circuit artifacts to `circuits/0.1.0` (`CIRCUITS_BASE_URL` in
  `src/constants.rs`, with no override on `TransactOptions`), while the program at
  `zh1eLd6rSphLejbFfJEneUwzHRfMKxgzrgkfwA6qRkW` verifies against the 0.2.0 verifying key.
  Any proof from this crate is rejected with `0x1010` (`ProofInvalid`) on every cluster
  running that program build, mainnet included. The transaction fails atomically, so the
  deposit is not lost, but the fee is spent and there is no working integration until the
  crate is republished against `circuits/0.2.0`. For anything you intend to land on chain
  today, use the TypeScript SDK (`@cloak.dev/sdk@0.2.0`), or seed the artifact cache with the
  0.2.0 bundle as shown in the [Rust SDK introduction](/sdk/rust/introduction).
</Warning>

## Prerequisites

- Rust 1.85+ (edition 2024 requires 1.85.0 or newer)
- A funded Solana keypair (see the warning above before you choose a cluster)
- A Solana RPC endpoint

## A SOL deposit end-to-end

```rust
use std::sync::Arc;

use cloak_sdk::{
    constants::{MIN_DEPOSIT_LAMPORTS, NATIVE_SOL_MINT},
    core::{
        transact::{transact, TransactOptions},
        utxo::{Utxo, UtxoKeypair},
    },
    rpc::SolanaRpc,
    utils::crypto::fr_to_bytes_be,
};
use solana_keypair::Keypair;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    // ---- 1. Wire up RPC + payer -----------------------------------------
    let rpc = Arc::new(SolanaRpc::new("<your RPC endpoint>")); // see the warning above
    let payer = Arc::new(Keypair::new()); // replace with a funded keypair

    // ---- 2. Create the output UTXO --------------------------------------
    // A UTXO is (keypair, blinding, amount, mint). `Utxo::new` draws the
    // `blinding` at random and keeps it only inside the value it returns:
    // the chain stores nothing but the Poseidon commitment. Clone the note
    // now, because `output` is about to move into `TransactOptions`.
    let utxo_kp = UtxoKeypair::generate()?;
    let output = Utxo::new(MIN_DEPOSIT_LAMPORTS, utxo_kp, NATIVE_SOL_MINT)?;
    let mut note = output.clone();

    // ---- 3. Describe the transaction ------------------------------------
    let opts = TransactOptions {
        // Flow shape: no inputs, one output, external_amount > 0 = deposit.
        inputs: vec![],
        outputs: vec![output],
        external_amount: MIN_DEPOSIT_LAMPORTS as i64,

        // Handles
        rpc: Some(rpc),
        payer: Some(payer),
        relay_url: Some("https://api.cloak.ag".into()),

        ..Default::default()
    };

    // ---- 4. Run the engine ----------------------------------------------
    let result = transact(opts).await?;

    // ---- 5. Persist the note before you touch anything else --------------
    // `output_indices[0]` is the leaf index assigned to `outputs[0]`.
    // Reconciliation is best-effort, so `None` is a normal outcome: store
    // the note anyway and backfill the index later by matching
    // `result.output_commitments[0]` against the tree. Never drop a note
    // because its index is missing.
    note.index = result.output_indices[0];
    save_note(&note)?;

    println!("signature: {}", result.signature);
    println!("output commitments: {:?}", result.output_commitments);
    println!("assigned leaf indices: {:?}", result.output_indices);

    // Cache the post-tx Merkle tree for the next transact to skip
    // `/commitments` on the next call:
    if let Some(tree) = &result.cached_merkle_tree {
        println!("cached tree has {} leaves", tree.len());
    }

    Ok(())
}

/// The five values that make a note spendable. `private_key` and `blinding`
/// are secrets: this plain-text file is a demo, encrypt them at rest the way
/// you would any wallet secret. In production implement
/// `cloak_sdk::storage::note_store::NoteStore` over sled / sqlite / Postgres
/// and call `insert(note)` here instead.
fn save_note(note: &Utxo) -> anyhow::Result<()> {
    let hex = |b: [u8; 32]| b.iter().map(|x| format!("{x:02x}")).collect::<String>();
    let label = note.index.map_or("pending".to_string(), |i| i.to_string());
    std::fs::write(
        format!("cloak-note-{label}.txt"),
        format!(
            "amount={}\nmint={}\nprivate_key={}\nblinding={}\nindex={:?}\n",
            note.amount,
            note.mint,
            hex(fr_to_bytes_be(&note.keypair.private_key)),
            hex(fr_to_bytes_be(&note.blinding)),
            note.index,
        ),
    )?;
    Ok(())
}
```

## What just happened

1. **Preflight** (synchronous, pure): validated arity / balance / mint, classified the flow as `Deposit`, and padded inputs to the fixed 2-in/2-out arity.
2. **Viewing-key registration** (skipped by default — flip `require_viewing_key` to enable): challenge + register with the payer signing the message.
3. **Merkle fetch**: pulled the on-chain tree state via RPC and the commitment set via `/commitments`, falling back to a frontier proof if needed.
4. **Circuit input packing**: 90 decimal-string signals, in the exact order the circom transaction circuit consumes.
5. **Proof generation**: ark-circom + ark-groth16 emitted a 256-byte proof. Artifacts (wasm + zkey) cache under `~/Library/Caches/cloak-sdk/circuits/0.1.0/` on macOS, `~/.cache/cloak-sdk/circuits/0.1.0/` on Linux. That pinned `0.1.0` version is the constraint described in the warning at the top of this page, and the directory name is derived from the constant, so it does not change even after you seed it with the `0.2.0` bundle. Only that `0.2.0` ceremony bundle is accepted by the deployed program (see [Release notes 2026-08](/releases/2026-08-mainnet)).
6. **Chain-note encryption**: a single compact v2 note bound to the primary output commitment, encrypted under HKDF-derived AES-256-GCM.
7. **Direct submission**: compiled a v0 transaction, signed with the payer, auto-created an ephemeral ALT if the tx exceeded 1232 bytes, retried on blockhash expiry and transient transport errors.
8. **Commitment reconciliation**: best-effort poll against `/commitments` to fill `output_indices`.

All this is one `transact(opts).await?` call.

## What `transact()` does not do: keep your notes

Step 5 above is not boilerplate. The engine has no wallet and no storage, so persisting
output notes is entirely yours.

A note is spendable only by whoever holds its `UtxoKeypair.private_key` together with its
exact `blinding`. `Utxo::new` draws that `blinding` from `random_field_element()` and
keeps it only inside the value it returns; the on-chain leaf is nothing but
`Poseidon(amount, public_key, blinding, mint_field)`.

<Warning>
  An output you constructed and then dropped is unspendable by you and by everyone else,
  permanently. Nothing recovers it: the encrypted chain note carries an 8-byte timestamp,
  not the blinding, so no scan of the chain can rebuild the note. On a transfer, a
  withdrawal, or a swap the output that hurts is the **change**, because that is the
  balance you kept.
</Warning>

The pattern is the same at every call site: clone each output `Utxo` before it moves into
`TransactOptions.outputs` (`Utxo` and `UtxoKeypair` both derive `Clone`), write
`result.output_indices[i]` into the clone's `index`, and store it before you use the
result for anything else. `cloak_sdk::storage::note_store::NoteStore` is the trait to
implement for that; the crate ships the trait, not a backend.

## Chaining transactions

Thread the returned tree and ALTs into the next call to avoid repeating work. Every
output still has to be cloned and stored:

```rust
let first = transact(deposit_opts).await?;

// `deposit_note` is the deposit's output note, cloned before `deposit_opts`
// moved (`let mut deposit_note = output.clone();`, the `note` variable in the
// first sample). Give it its index and store it before anything else.
deposit_note.index = first.output_indices[0];
save_note(&deposit_note)?;

// outputs[0] is the recipient's note, outputs[1] is your change. A recipient
// can only spend outputs[0] once they hold that `UtxoKeypair`; delivering it
// to them is your application's job, the protocol does not do it.
let recipient_output = Utxo::new(send_amount, recipient_keypair, mint)?;
let change_output = Utxo::new(deposit_note.amount - send_amount, UtxoKeypair::generate()?, mint)?;
let mut change_note = change_output.clone();

let transfer_opts = TransactOptions {
    // Spend the output we just created
    inputs: vec![deposit_note],
    outputs: vec![recipient_output, change_output],
    external_amount: 0, // shield-to-shield transfer
    cached_merkle_tree: first.cached_merkle_tree,
    address_lookup_table_accounts: first.address_lookup_table_accounts,
    ..base_opts
};

let second = transact(transfer_opts).await?;

// The change note is your remaining balance. Store it before you log, print,
// or return anything from `second`.
change_note.index = second.output_indices[1];
save_note(&change_note)?;
```
